# labtrace
项目简介：面向实验室场景，基于 STM32+FreeRTOS的嵌入式物联网追溯系统。
	采用“终端采集—服务端持久化—客户端监控”三级架构。STM32 终端完成试剂 RFID 身份识别、称重采集、环境监测与门禁控制，Qt 服务端实现 MQTT 设备接入、数据校验与幂等存储，Qt 客户端提供实时监控与远程交互能力，解决传统人工登记模式下试剂去向不明、库存失控、实验事故无法溯源的痛点。
- STM32终端：完成RFID身份识别、称重采集、环境监测、门禁控制，断网本地缓存记录
- Qt服务端：MQTT设备接入、数据校验、SQLite幂等入库、TCP中转
- Qt客户端：实时数据监控、远程门禁控制

 硬件平台
| 外设 | 连接总线 | 功能 |
|------|----------|------|
| STM32F103C8T6 | 主控 | 业务逻辑运行，FreeRTOS多任务调度 |
| RC522射频模块 | SPI1 | 试剂/人员RFID身份识别 |
| W25Q64外部Flash | SPI2 | 离线业务记录持久化缓存 |
| ESP8266 | USART2 | WiFi连接，MQTT上云通信 |
| HX711称重传感器 | GPIO | 试剂在位/称重检测 |
| DHT11温湿度 | GPIO | 实验室环境监测 |

 核心技术实现
# 1. FreeRTOS多任务调度
拆分6个差异化优先级任务，通过消息队列、二值信号量、互斥锁完成任务间解耦，替代全局变量方案，规避多任务数据竞争：
- 业务状态机TraceTask串联刷卡验证、开门、在位检测、前后称重、归还复核全流程，关键节点配置超时保护，异常自动回退空闲态，避免任务卡死
- 网络任务、Flash存储任务独立划分，网络阻塞不影响主业务流程

# 2. 高可靠离线缓存设计
基于W25Q64实现断网不丢数据：
- 分配4KB独立扇区，划分32个128字节固定槽位，采用pending/sent双状态标记管理
- 自定义槽位格式：固定魔术字校验 + 全记录CRC32校验 + 全局递增seq唯一序号，校验通过才写入Flash
- 严格遵循「先本地落盘 → MQTT上报成功 → 才标记记录为sent」时序，中途断电不丢记录、不重复上报
- 网络恢复后自动扫描pending槽位，按seq顺序补发离线记录

# 3. 通信可靠性设计
- 串口分帧：USART接收中断仅存字节，300ms静默超时判断帧结束，解决AT响应粘包半包
- MQTT通信：自动重连机制，检测到网络断开/模块重启自动5秒后重连，断线期间业务正常运行
- 服务端TCP层：采用JSON + 换行符分帧解决TCP粘包半包，设计命令下发+结果回执两级反馈
- 下行命令三层校验：匹配设备专属主题 + 设备ID字段 + 命令类型，防止公共Broker误触发执行部件

 
 编译环境
- Keil MDK 5.38
- STM32CubeMX 1.6.0
- 编译输出：Flash占用35.6KB / RAM占用17.9KB（STM32F103C8T6 64KB Flash / 20KB RAM）

 说明
- 项目使用公共免费MQTT测试Broker（broker.hivemq.com），无硬编码敏感信息
- STM32端包含完整业务逻辑，编译时需配合STM32CubeMX生成HAL/FreeRTOS工程骨架后，将App目录代码导入即可编译

## Qt服务端实现
- 基于QtMqtt实现多设备接入，订阅设备遥测主题，JSON字段校验后入库
- SQLite建表加`device_id+seq`联合唯一索引，参数绑定+INSERT OR IGNORE实现幂等写入，解决MQTT重发、Flash补发的重复数据问题
- 封装TCP中转层，监听6666端口，JSON+换行符分帧解决粘包，推送实时数据到Qt客户端
- 内嵌轻量Web监控页，浏览器直接访问即可查看实时数据
